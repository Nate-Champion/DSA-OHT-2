Tree vocabulary
RootThe topmost node — no parent. A non-empty tree has exactly one.
Parent / ChildAn immediate predecessor is the parent; immediate successors are children.
LeafA node with no children (an external node).
Internal nodeA node with at least one child.
SiblingsChildren of the same parent.
Ancestor / DescendantEverything on the path from the root down to a node are its ancestors; everything below it are descendants.
LevelNumber of edges from the root. The root sits at level 0.
HeightLength of the longest path from a node down to a leaf.
SubtreeAny node together with all of its descendants.
DegreeNumber of children — at most 2 in a binary tree.
Types of binary trees
BalancedFor every node the left and right subtree heights differ by at most 1.
CompleteAll levels full except possibly the last, filled left → right.
Full / StrictEvery node has either 0 or 2 children.
Almost completeChildren are added left-first; each level fills before the next begins.
PerfectAll leaves on the same level, every internal node has 2 children. Perfect ⇒ full + complete + balanced.
Depth-first traversals
Inorder · L–Root–RLeft subtree, then the node, then the right subtree. On a BST this yields the keys in sorted order.
Preorder · Root–L–RThe node first, then left, then right. Useful for copying or serialising a tree.
Postorder · L–R–RootChildren before the parent. Useful for deleting a tree bottom-up.
Level order · BFSLevel 0, then level 1, then level 2 … implemented with a queue.
Binary search tree rules
Rule 1The left subtree holds only keys smaller than the node's key.
Rule 2The right subtree holds only keys greater than the node's key.
Rule 3Both subtrees are themselves BSTs (recursive property).
Rule 4No duplicate keys — or a fixed duplicate-handling policy.
CostSearch, insert, delete, min, max, floor, ceil all run in O(h). A degenerate chain makes h = n.
Why self-balanceAVL and red–black trees keep h = O(log n), turning every operation into O(log n).
BFS vs DFS
BFSUses a queue (FIFO). Builds the tree level by level. Great for shortest paths in unweighted graphs.
DFSUses a stack or recursion (LIFO). Dives as deep as possible before backtracking.
MemoryBFS may hold a whole level; DFS holds only the current path.

Step-by-step explanation
    What makes a tree an AVL tree?
    Self-balancing BSTNamed after Adelson-Velsky and Landis. For every node, the left and right subtree heights differ by at most 1.
    Balance factorBF(node) = height(left) − height(right). Allowed values −1, 0, +1.
    Height boundHeld at O(log n). Max nodes at height H is 2H+1 − 1.
    OperationsSearch, insert and delete are all O(log n). Insertion and deletion also perform rotations.
    The four rotation cases
    LL · Left-LeftInserted into the left subtree of the left child → a single right rotation.
    RR · Right-RightInserted into the right subtree of the right child → a single left rotation.
    LR · Left-RightInserted into the right subtree of the left child → left-rotate the child, then right-rotate the node.
    RL · Right-LeftInserted into the left subtree of the right child → right-rotate the child, then left-rotate the node.
    AVL vs Red–Black
    AVL is stricterHeight difference ≤ 1 gives a shorter, bushier tree and faster lookups.
    More rotationsThe strict rule means AVL insertion and deletion perform more rotations.
    Red–Black is looserHeight ≤ 2·log₂(n+1). Fewer rotations, faster updates — that's why C++ std::map and Java TreeMap use red–black trees.
    Pick AVL whenReads dominate writes, in-memory dictionaries, real-time systems needing predictable O(log n).

      The five red–black rules
      1 · ColourEvery node is either red or black.
      2 · RootThe root is always black.
      3 · LeavesEvery null child counts as a black leaf (NIL).
      4 · No red-redA red node can never have a red child.
      5 · Black heightEvery path from a node down to a leaf contains the same number of black nodes.
      Why botherThese rules keep the height ≤ 2·log₂(n+1), so search, insert and delete are all O(log n).

        How Prim's algorithm works
        Step 1Start from any vertex — it forms a one-vertex tree.
        Step 2Look at every edge with exactly one endpoint inside the tree.
        Step 3Take the cheapest of those crossing edges and pull its outside vertex in.
        Step 4Repeat until every vertex is inside — that is the minimum spanning tree. With a binary heap this runs in O(E log V).
